Bước 01

Linux cho DevOps: cẩm nang lệnh đầy đủ

19 nhóm lệnh Linux mà một kỹ sư DevOps dùng hàng ngày — từ điều hướng file cơ bản đến systemd, mạng, và nền tảng container. Mỗi mục có mô tả ngắn và ví dụ chạy được thật.

01 Terminal & Shell

Shell là chương trình thông dịch lệnh bạn gõ. Mặc định trên hầu hết distro là bash; các distro hiện đại (Ubuntu, Fedora) đôi khi dùng zsh. Biết cách tự tra cứu (man, --help) quan trọng hơn thuộc lòng mọi lệnh.

LệnhMô tảVí dụ
manXem trang hướng dẫn đầy đủ của một lệnh.man chmod
--helpXem tóm tắt cờ (flag) của lệnh, nhanh hơn man.tar --help
whatisMô tả 1 dòng về lệnh.whatis grep
typeXem lệnh là alias, builtin, hay file thực thi.type ls
whichĐường dẫn tuyệt đối của một binary trong $PATH.which python3
historyXem lịch sử lệnh đã gõ.history | grep ssh
clearXóa màn hình terminal.clear
whoamiNgười dùng hiện tại.whoami
uname -aThông tin kernel, kiến trúc, hostname.uname -a
hostnamectlThông tin hệ thống chi tiết (systemd).hostnamectl
/etc/os-releaseXem tên và version distro đang chạy.cat /etc/os-release
Ghi chú distro: lệnh cốt lõi (ls, grep, chmod…) giống nhau ở mọi bản phân phối. Khác biệt chính nằm ở trình quản lý gói: Debian/Ubuntu dùng apt, RHEL/CentOS/Fedora dùng dnf/yum — xem mục 09.

02 File & thư mục

Nền tảng của mọi thao tác trên Linux. find đặc biệt quan trọng để dọn log, tìm file cấu hình, hay chạy hàng loạt qua xargs.

LệnhMô tảVí dụ
pwdIn đường dẫn thư mục hiện tại.pwd
cdĐổi thư mục làm việc.cd /var/log && cd -
ls -laLiệt kê file kèm ẩn, quyền, chủ sở hữu.ls -lah /etc
treeXem cây thư mục dạng phân cấp.tree -L 2
mkdir -pTạo thư mục, kể cả thư mục cha chưa tồn tại.mkdir -p app/logs/2026
touchTạo file rỗng hoặc cập nhật timestamp.touch deploy.log
cp -rSao chép file/thư mục (đệ quy với -r).cp -r configs/ backup/
mvDi chuyển hoặc đổi tên.mv app.log app.log.bak
rm -rfXóa file/thư mục đệ quy, không hỏi lại. Dùng cẩn thận.rm -rf ./tmp_build
findTìm file theo tên, thời gian, kích thước, quyền…find /var/log -name "*.log" -mtime +7
find … -execChạy lệnh trên từng kết quả tìm được.find . -name "*.tmp" -exec rm {} \;
locateTìm file nhanh qua database (cần updatedb).locate nginx.conf
ln -sTạo symbolic link.ln -s /opt/app/current /opt/app/live
statThông tin chi tiết inode: quyền, thời gian, kích thước.stat Dockerfile
fileXác định loại file thực tế (không dựa vào phần mở rộng).file ./binary
basename / dirnameTách tên file / thư mục cha từ một đường dẫn.basename /opt/app/run.sh
realpathĐường dẫn tuyệt đối, đã resolve symlink.realpath ../shared/config.yml
du -shTổng dung lượng một thư mục.du -sh /var/lib/docker

03 Xử lý văn bản (text processing)

DevOps sống trong log và file cấu hình dạng text. Bộ ba grep + sed + awk là công cụ mạnh nhất bạn có.

LệnhMô tảVí dụ
catIn toàn bộ nội dung file ra màn hình.cat /etc/hosts
lessXem file dài, cuộn trang, tìm kiếm bằng /.less /var/log/syslog
head / tailXem đầu/cuối file. -f để theo dõi realtime.tail -f /var/log/nginx/access.log
wcĐếm dòng (-l), từ (-w), byte (-c).wc -l access.log
grepTìm dòng khớp pattern. -i, -r, -n, -v, -E.grep -rniE "error|fail" /var/log/app/
sedTìm-thay thế văn bản theo dòng, hoặc xóa/chèn dòng.sed -i 's/DEBUG/INFO/g' config.env
awkXử lý dữ liệu dạng cột, tính toán, lọc theo điều kiện.awk '{print $1, $NF}' access.log
cutCắt cột theo delimiter hoặc vị trí ký tự.cut -d: -f1 /etc/passwd
sortSắp xếp dòng (-n số, -r ngược, -u duy nhất).sort -nr scores.txt
uniqLoại dòng trùng liền kề, thường đi sau sort.sort ips.txt | uniq -c | sort -nr
trThay thế/xóa ký tự.echo "HELLO" | tr 'A-Z' 'a-z'
diffSo sánh khác biệt giữa hai file.diff config.old config.new
teeGhi ra file đồng thời in ra màn hình (dùng trong pipe).echo "OK" | tee -a status.log
column -tCăn dữ liệu thành bảng dễ đọc.cat data.csv | column -t -s,
Pipe (|) nối các lệnh này lại: cat access.log | grep 500 | awk '{print $1}' | sort | uniq -c | sort -nr | head — đếm IP gây lỗi 500 nhiều nhất.

04 Phân quyền (permissions)

Mỗi file có 3 nhóm quyền: chủ sở hữu (owner), nhóm (group), người khác (other), mỗi nhóm có read/write/execute.

LệnhMô tảVí dụ
chmodĐổi quyền, dạng số (755) hoặc ký hiệu (u+x).chmod 750 deploy.sh
chownĐổi chủ sở hữu file/thư mục.chown -R app:app /opt/app
chgrpĐổi nhóm sở hữu.chgrp deploy release.tar
umaskQuyền mặc định khi tạo file mới.umask 022
getfacl / setfaclQuyền chi tiết hơn owner/group/other (ACL).setfacl -m u:web:rx /srv/data
sudoChạy lệnh với quyền user khác (thường là root).sudo systemctl restart nginx
suChuyển sang user khác trong shell hiện tại.su - postgres
visudoSửa /etc/sudoers an toàn.sudo visudo
Số quyền = tổng r(4)+w(2)+x(1). 755 = owner rwx, group r-x, other r-x. 644 = chuẩn cho file cấu hình chỉ đọc.

06 Quản lý dịch vụ với systemd

Hầu hết distro hiện đại dùng systemd làm init system (PID 1) — quản lý service, log tập trung qua journal, và lịch chạy qua timer.

LệnhMô tảVí dụ
systemctl start/stop/restartĐiều khiển vòng đời service.systemctl restart docker
systemctl reloadNạp lại cấu hình mà không ngắt kết nối.systemctl reload nginx
systemctl statusTrạng thái, PID, log gần nhất của service.systemctl status sshd
systemctl enable/disableBật/tắt tự khởi động cùng hệ thống.systemctl enable --now docker
systemctl is-active / is-enabledKiểm tra nhanh trạng thái, dùng tốt trong script.systemctl is-active nginx
systemctl list-units --type=serviceDanh sách service đã load (mặc định ẩn unit inactive — thêm --all để xem toàn bộ).systemctl list-units --all --type=service
systemctl daemon-reloadNạp lại sau khi sửa unit file.sudo systemctl daemon-reload
journalctl -uLog của một service cụ thể.journalctl -u nginx -f
journalctl -bLog từ lần boot hiện tại.journalctl -b -p err
journalctl --sinceLọc log theo khoảng thời gian.journalctl --since "1 hour ago"
systemd-analyzeThời gian boot, service nào khởi động chậm.systemd-analyze blame
Unit file cơ bản (/etc/systemd/system/myapp.service): 
[Unit]
Description=My App
After=network.target

[Service]
ExecStart=/opt/app/run.sh
Restart=on-failure
User=app

[Install]
WantedBy=multi-user.target

15 Viết Bash script cơ bản

Tự động hóa là lý do DevOps tồn tại. Một script tối thiểu cần: shebang, xử lý tham số, kiểm tra điều kiện, và exit code rõ ràng.

#!/usr/bin/env bash
set -euo pipefail   # dừng ngay khi có lỗi, biến chưa khai báo, hoặc lỗi trong pipe

ENV="${1:-staging}"
LOG_DIR="/var/log/deploy"

if [[ ! -d "$LOG_DIR" ]]; then
  mkdir -p "$LOG_DIR"
fi

for service in api worker scheduler; do
  echo "Deploying $service to $ENV..."
  systemctl restart "$service" || {
    echo "Failed to restart $service" >&2
    exit 1
  }
done

echo "Deploy to $ENV completed."
Cú phápMô tả
$1 $2 … $@ $#Tham số dòng lệnh: từng tham số, toàn bộ, và số lượng.
$?Exit code của lệnh vừa chạy — 0 là thành công.
if / elif / else / fiRẽ nhánh điều kiện.
for / whileVòng lặp qua danh sách hoặc theo điều kiện.
function name() { ... }Định nghĩa hàm tái sử dụng.
set -euo pipefailChế độ "strict" nên bật ở đầu mọi script production.
