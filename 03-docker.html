Bước 03

Docker cho DevOps

Đóng gói ứng dụng thành container để chạy nhất quán mọi nơi. 10 phần đi từ kiến trúc, lệnh cốt lõi, Dockerfile, đến Compose và bảo mật container.

01 Docker là gì & kiến trúc

Docker đóng gói ứng dụng cùng toàn bộ dependency vào một đơn vị chạy độc lập, dựa trên namespaces & cgroups của Linux (xem lại mục 17 ở Bước 1).

Khái niệmMô tả
ImageBản đóng gói bất biến gồm code, dependency, runtime — dùng làm khuôn để tạo container.
ContainerMột instance đang chạy của image, cô lập tài nguyên bằng namespaces/cgroups.
Docker daemon (dockerd)Tiến trình nền quản lý image, container, network, volume.
Docker CLIGiao diện dòng lệnh gửi lệnh tới daemon qua REST API.
RegistryKho lưu trữ image — Docker Hub, Amazon ECR, GitHub Container Registry.
DockerfileFile định nghĩa từng bước để build một image.
Container không phải máy ảo — nó chia sẻ kernel với host, chỉ cô lập tiến trình/mạng/filesystem, nên khởi động gần như tức thì và nhẹ hơn VM rất nhiều.

02 Quản lý Image

Vòng đời của một image: tải về, build, gắn tag, đẩy lên registry.

LệnhMô tảVí dụ
docker pullTải image từ registry về máy.docker pull nginx:1.27
docker imagesLiệt kê image đang có ở local.docker images
docker buildBuild image từ Dockerfile.docker build -t myapp:1.0 .
docker tagGắn thêm tên/tag cho một image đã build.docker tag myapp:1.0 myrepo/myapp:1.0
docker pushĐẩy image lên registry.docker push myrepo/myapp:1.0
docker rmiXóa image khỏi máy local.docker rmi myapp:1.0
docker image pruneDọn image không còn container nào dùng (dangling).docker image prune -a
docker historyXem từng layer đã tạo nên image.docker history myapp:1.0
Không bao giờ dùng tag latest cho production — luôn ghi rõ version hoặc git SHA để biết chính xác đang chạy bản nào, và để rollback dễ dàng.

03 Quản lý Container

Chạy, theo dõi, và điều khiển vòng đời container.

LệnhMô tảVí dụ
docker runTạo và chạy container mới từ một image.docker run -d -p 8080:80 --name web nginx
docker psLiệt kê container đang chạy (-a để xem cả container đã dừng).docker ps -a
docker stop/start/restartDừng/chạy lại/khởi động lại container.docker restart web
docker exec -itMở shell hoặc chạy lệnh bên trong container đang sống.docker exec -it web bash
docker logs -fXem log của container, -f để theo dõi realtime.docker logs -f web
docker inspectXem chi tiết cấu hình, IP, mount, env của container.docker inspect web
docker rmXóa container đã dừng.docker rm web
docker statsTheo dõi CPU/RAM realtime theo container.docker stats
docker cpCopy file giữa container và host.docker cp web:/app/log.txt ./
Cờ hay dùng của docker run: -d chạy nền, -p host:container map port, -v mount volume, -e biến môi trường, --name đặt tên, --rm tự xóa khi dừng.

04 Dockerfile

Dockerfile là công thức để build image — mỗi dòng tạo ra một layer, layer được cache để build lại nhanh hơn.

Chỉ thịMô tả
FROMBase image làm nền để build tiếp.
WORKDIRĐặt thư mục làm việc cho các lệnh phía sau.
COPY / ADDCopy file từ máy build vào image (ADD hỗ trợ thêm giải nén/URL).
RUNChạy lệnh trong lúc build (cài dependency, compile...).
ENV / ARGBiến môi trường tồn tại lúc chạy (ENV) hoặc chỉ lúc build (ARG).
EXPOSEKhai báo port ứng dụng lắng nghe (chỉ mang tính tài liệu, không tự mở port).
USERChuyển sang user không phải root để chạy ứng dụng.
CMD / ENTRYPOINTLệnh chạy khi container khởi động.
HEALTHCHECKLệnh Docker tự chạy định kỳ để kiểm tra container còn khỏe không.
FROM node:20-alpine
WORKDIR /app

# Cài dependency trước để tận dụng cache layer
COPY package*.json ./
RUN npm ci --omit=dev

COPY . .

ENV NODE_ENV=production
EXPOSE 3000

USER node
CMD ["node", "server.js"]
Đặt COPY package*.json và npm ci trước khi copy toàn bộ source — nếu chỉ code thay đổi mà dependency không đổi, Docker tái sử dụng layer cài đặt đã cache, build nhanh hơn nhiều.

05 Volumes & lưu trữ dữ liệu bền vững

Dữ liệu ghi bên trong container sẽ mất khi container bị xóa — volume giúp dữ liệu tồn tại độc lập với vòng đời container.

Khái niệmMô tảVí dụ
Named volumeDocker tự quản lý vị trí lưu trữ, di động và dễ backup nhất.docker volume create dbdata
Bind mountGắn trực tiếp một thư mục cụ thể trên host vào container.docker run -v $(pwd)/src:/app/src myapp
tmpfs mountLưu trong RAM, mất khi container dừng — dùng cho dữ liệu tạm nhạy cảm.docker run --tmpfs /app/tmp myapp
docker volume ls / rmLiệt kê / xóa volume.docker volume ls

06 Networking trong Docker

Container giao tiếp với nhau và với thế giới bên ngoài qua các driver mạng của Docker.

DriverMô tả
bridge (mặc định)Mạng ảo riêng cho container trên cùng host, cần -p để expose port ra ngoài.
hostContainer dùng chung network stack với host, không cô lập port.
noneKhông có network, cô lập hoàn toàn.
custom bridge networkMạng bridge tự tạo — container trong cùng mạng này gọi nhau bằng tên thay vì IP.
LệnhMô tảVí dụ
docker network createTạo mạng bridge riêng cho một nhóm container.docker network create app-net
docker network lsLiệt kê mạng hiện có.docker network ls
docker run --networkChạy container trong một mạng cụ thể.docker run --network app-net --name api myapi
Trong cùng một custom network, container gọi nhau qua tên: ví dụ ứng dụng gọi database bằng hostname db thay vì IP — đây chính là cơ chế Docker Compose dùng bên dưới.

07 Docker Compose

Compose định nghĩa nhiều container liên quan (app, database, cache...) trong một file YAML, chạy cùng lúc bằng một lệnh.

services:
  api:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgres://db:5432/app
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    volumes:
      - dbdata:/var/lib/postgresql/data
    environment:
      - POSTGRES_PASSWORD=changeme

volumes:
  dbdata:
LệnhMô tảVí dụ
docker compose up -dKhởi động toàn bộ service trong nền.docker compose up -d
docker compose downDừng và xóa container, network (giữ volume trừ khi thêm -v).docker compose down
docker compose logs -fXem log của tất cả service.docker compose logs -f api
docker compose psTrạng thái các service.docker compose ps
docker compose execChạy lệnh trong một service đang sống.docker compose exec api sh

08 Multi-stage build & tối ưu image

Image càng nhỏ càng deploy nhanh và giảm bề mặt tấn công. Multi-stage build tách giai đoạn build (cần compiler, dev dependency) khỏi giai đoạn chạy (chỉ cần runtime).

# Stage 1: build
FROM node:20 AS builder
WORKDIR /app
COPY . .
RUN npm ci && npm run build

# Stage 2: chạy — chỉ copy kết quả build, không mang theo dev dependency
FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
CMD ["node", "dist/server.js"]
Kỹ thuậtMô tả
.dockerignoreLoại trừ file không cần thiết (node_modules, .git, log) khỏi build context — build nhanh hơn, image sạch hơn.
Base image nhỏƯu tiên alpine hoặc distroless thay vì image full OS khi có thể.
Gộp lệnh RUNGộp nhiều RUN apt-get install && rm -rf /var/lib/apt/lists/* vào một layer để giảm kích thước.

09 Debug & troubleshooting

Container "không chạy" hoặc "restart liên tục" — đây là thứ tự kiểm tra chuẩn.

LệnhMô tảVí dụ
docker logsXem log để tìm lỗi ứng dụng gây crash.docker logs --tail 100 web
docker exec -it ... shVào bên trong container đang chạy để kiểm tra trực tiếp.docker exec -it web sh
docker inspectXem exit code, mount, network config chi tiết.docker inspect --format='{{.State.ExitCode}}' web
docker eventsTheo dõi realtime sự kiện start/stop/die của container.docker events
docker system dfXem dung lượng đĩa Docker đang chiếm (image, container, volume).docker system df
docker system pruneDọn toàn bộ container/image/network không dùng.docker system prune -a --volumes
Container restart loop thường do: ứng dụng crash ngay khi khởi động (xem logs), thiếu biến môi trường bắt buộc, hoặc healthcheck fail liên tục — kiểm tra theo đúng thứ tự trên trước khi nghi ngờ hạ tầng.

10 Bảo mật container

  • Không chạy tiến trình bên trong container bằng root — luôn khai báo USER trong Dockerfile.
  • Dùng base image tối thiểu (alpine/distroless), giảm bề mặt tấn công.
  • Không bao giờ hard-code secret vào image — truyền qua biến môi trường lúc chạy hoặc secret manager.
  • Luôn pin version cụ thể cho base image, không dùng latest.
  • Quét lỗ hổng image trước khi deploy (Trivy, Docker Scout, Grype).
  • Giới hạn tài nguyên container để tránh một container chiếm hết CPU/RAM host (--memory, --cpus).
  • Dùng .dockerignore để không vô tình đóng gói file nhạy cảm (.env, khóa SSH) vào image.
