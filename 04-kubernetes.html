Bước 04

Kubernetes cho DevOps

Điều phối hàng trăm container một cách tự động: tự phục hồi, tự scale, tự cập nhật. 11 phần đi từ kiến trúc, các resource cốt lõi, đến Helm và debug thực chiến.

01 Kiến trúc Kubernetes

Một cluster Kubernetes gồm 2 nhóm máy: Control Plane (bộ não điều phối) và Worker Node (nơi container thực sự chạy).

Control Plane

Thành phầnMô tả
kube-apiserverCổng giao tiếp duy nhất — mọi lệnh kubectl và thành phần khác đều đi qua đây.
etcdCơ sở dữ liệu key-value lưu toàn bộ trạng thái cluster.
kube-schedulerQuyết định Pod mới được đặt lên node nào dựa trên tài nguyên còn trống.
kube-controller-managerChạy các vòng lặp điều khiển đảm bảo trạng thái thực tế khớp trạng thái mong muốn.

Worker Node

Thành phầnMô tả
kubeletAgent trên mỗi node, đảm bảo container trong Pod thực sự chạy đúng như khai báo.
kube-proxyQuản lý rule mạng để traffic tới Service được định tuyến đúng Pod.
Container runtimePhần mềm thực sự chạy container (containerd, CRI-O).
Nguyên lý cốt lõi: bạn khai báo trạng thái mong muốn (declarative, qua YAML) — Kubernetes liên tục điều chỉnh để trạng thái thực tế khớp với nó (reconciliation loop).

02 kubectl — lệnh cơ bản

kubectl là CLI chính để tương tác với cluster qua kube-apiserver.

LệnhMô tảVí dụ
kubectl getLiệt kê resource.kubectl get pods -n prod
kubectl describeXem chi tiết + sự kiện gần nhất của một resource.kubectl describe pod api-7d9f
kubectl apply -fTạo hoặc cập nhật resource từ file YAML.kubectl apply -f deployment.yaml
kubectl deleteXóa resource.kubectl delete pod api-7d9f
kubectl logs -fXem log container trong Pod.kubectl logs -f api-7d9f -c app
kubectl exec -itMở shell bên trong container.kubectl exec -it api-7d9f -- sh
kubectl get all -nXem tổng quan mọi resource trong một namespace.kubectl get all -n prod
kubectl config use-contextChuyển giữa nhiều cluster đã cấu hình.kubectl config use-context staging

03 Pod — đơn vị nhỏ nhất

Pod là đơn vị triển khai nhỏ nhất trong Kubernetes — thường chứa 1 container, đôi khi thêm container phụ (sidecar) chia sẻ network/volume.

apiVersion: v1
kind: Pod
metadata:
  name: api
  labels:
    app: api
spec:
  containers:
    - name: app
      image: myrepo/api:1.4.0
      ports:
        - containerPort: 3000
      resources:
        requests:
          cpu: "100m"
          memory: "128Mi"
        limits:
          cpu: "500m"
          memory: "256Mi"
Thực tế hiếm khi tạo Pod trực tiếp — luôn tạo thông qua Deployment (mục 04) để có tự phục hồi và rolling update.

04 Deployment & ReplicaSet

Deployment quản lý ReplicaSet, ReplicaSet quản lý số lượng Pod — đây là cách chuẩn để chạy ứng dụng stateless.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
        - name: app
          image: myrepo/api:1.4.0
LệnhMô tảVí dụ
kubectl scaleĐổi số lượng replica.kubectl scale deployment api --replicas=5
kubectl rollout statusTheo dõi tiến trình rolling update.kubectl rollout status deployment/api
kubectl rollout undoRollback về version trước.kubectl rollout undo deployment/api
kubectl rollout historyXem lịch sử các lần deploy.kubectl rollout history deployment/api

05 Service

Pod có IP thay đổi liên tục khi bị tạo lại — Service cấp một địa chỉ ổn định để gọi vào nhóm Pod phía sau.

LoạiMô tả
ClusterIP (mặc định)Chỉ truy cập được từ bên trong cluster.
NodePortMở thêm một port cố định trên mọi node để truy cập từ ngoài cluster.
LoadBalancerCloud provider (AWS ELB/NLB) tự cấp một load balancer bên ngoài trỏ vào Service.
ExternalNameÁnh xạ Service sang một DNS name bên ngoài cluster.
apiVersion: v1
kind: Service
metadata:
  name: api
spec:
  selector:
    app: api
  ports:
    - port: 80
      targetPort: 3000
  type: ClusterIP

06 ConfigMap & Secret

Tách cấu hình khỏi image — cùng một image chạy được ở nhiều môi trường chỉ bằng cách đổi ConfigMap/Secret.

Khái niệmMô tảVí dụ
ConfigMapLưu cấu hình dạng plaintext (không nhạy cảm).kubectl create configmap app-config --from-literal=LOG_LEVEL=info
SecretLưu dữ liệu nhạy cảm, được mã hóa base64 (nên kết hợp thêm encryption at rest ở etcd).kubectl create secret generic db-secret --from-literal=password=changeme
Dùng trong Pod qua envFrom.configMapRef/secretRef, hoặc mount làm file qua volumes.configMap/secret.

07 Ingress

Ingress định tuyến traffic HTTP(S) từ bên ngoài vào đúng Service dựa trên domain/path, cần một Ingress Controller (thường là nginx) chạy trong cluster.

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: api-ingress
spec:
  rules:
    - host: api.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: api
                port:
                  number: 80
  tls:
    - hosts: [api.example.com]
      secretName: api-tls
Trên AWS thường dùng AWS Load Balancer Controller để Ingress tự tạo Application Load Balancer — tương đương khái niệm ALB ở Bước 2, mục 07.

08 Volume & PersistentVolume/PVC

Giống Docker, Pod cần volume để giữ dữ liệu qua vòng đời container — Kubernetes tách riêng "nơi lưu trữ vật lý" (PV) khỏi "yêu cầu sử dụng" (PVC).

Khái niệmMô tả
emptyDirVolume tạm, sống theo vòng đời Pod, mất khi Pod bị xóa.
hostPathMount trực tiếp một thư mục trên node — chỉ dùng cho trường hợp đặc biệt (agent, daemon).
PersistentVolume (PV)Đại diện cho một vùng lưu trữ vật lý thực sự (EBS, NFS...).
PersistentVolumeClaim (PVC)Yêu cầu của Pod về dung lượng/loại lưu trữ — Kubernetes tự gắn vào một PV phù hợp.
StorageClassĐịnh nghĩa loại lưu trữ (SSD, HDD...) để PV được cấp phát tự động (dynamic provisioning).

09 Namespace & RBAC

Namespace cách ly resource theo logic (team, môi trường); RBAC kiểm soát ai được làm gì trên resource nào.

Khái niệmMô tả
NamespaceKhông gian tên logic để nhóm resource — ví dụ tách staging/prod trong cùng cluster.
Role / RoleBindingCấp quyền trong phạm vi một namespace cụ thể.
ClusterRole / ClusterRoleBindingCấp quyền trên toàn cluster, xuyên namespace.
ServiceAccount"Danh tính" cho Pod khi nó cần gọi tới kube-apiserver hoặc dịch vụ cloud.
Nguyên tắc least-privilege (đã học ở Bước 2) áp dụng y hệt ở đây: mỗi ServiceAccount chỉ nên có đúng quyền cần thiết qua Role, không dùng quyền cluster-admin cho mọi thứ.

10 Helm — package manager cho Kubernetes

Helm đóng gói nhiều file YAML thành một "Chart" có thể cài đặt, nâng cấp, gỡ bỏ như một đơn vị duy nhất, tham số hóa qua values.yaml.

Khái niệm / LệnhMô tảVí dụ
ChartGói các template YAML + giá trị mặc định. 
ReleaseMột lần cài đặt cụ thể của Chart vào cluster. 
values.yamlFile cấu hình override giá trị mặc định của Chart. 
helm installCài đặt Chart thành một Release mới.helm install api ./chart -f values-prod.yaml
helm upgradeCập nhật Release đã tồn tại.helm upgrade api ./chart
helm rollbackQuay lại revision trước của Release.helm rollback api 2
helm uninstallGỡ bỏ Release.helm uninstall api

11 Debug & troubleshooting

Pod không chạy đúng — luôn bắt đầu bằng describe rồi mới tới logs.

LệnhMô tảVí dụ
kubectl describe podXem sự kiện (Events) gần nhất — lý do phổ biến nhất để tìm ra vấn đề.kubectl describe pod api-7d9f
kubectl logs --previousXem log của lần chạy trước, khi container vừa bị restart.kubectl logs api-7d9f --previous
kubectl get events --sort-byXem toàn bộ sự kiện trong namespace theo thời gian.kubectl get events --sort-by=.lastTimestamp
kubectl top pod/nodeXem CPU/RAM thực tế đang dùng (cần metrics-server).kubectl top pod -n prod

Các trạng thái Pod hay gặp

Trạng tháiNguyên nhân thường gặp
PendingKhông đủ tài nguyên trên node, hoặc PVC chưa được gắn.
ImagePullBackOffSai tên image/tag, hoặc thiếu quyền pull từ private registry.
CrashLoopBackOffỨng dụng bên trong container crash ngay khi khởi động — xem logs --previous.
OOMKilledContainer vượt quá resources.limits.memory và bị kernel kill.
